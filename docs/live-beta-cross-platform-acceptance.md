# Cross-platform live beta acceptance

This is the final operator gate for `live-0730-cross-platform-acceptance`. Run it with packaged
builds on Windows and macOS, two real users, and a third isolated profile. Automated and component
tests are prerequisites, not substitutes for this session.

## Before the session

1. Install the exact release candidate that the public download will serve on Windows and macOS.
2. Use three isolated test profiles: `alpha` on Windows, `bravo` on macOS, and `charlie` on either
   platform. Do not reuse a personal Harbor profile.
3. Record the OS versions and architectures, package signing/notarization state, Harbor version and
   commit, relay artifact, and relay namespace.
4. Confirm microphone and camera access can be granted on both primary platforms. Have a second
   network or hotspot available for relay/NAT behavior.
5. Choose one coordinator machine to own the only `session.json`. Copy already-sanitized evidence
   from the other host into this session directory; do not initialize a second manifest. Create the
   ignored evidence directory and initialize a new schema-versioned manifest. `--dir` may appear
   anywhere after the command and is the same in PowerShell, Command Prompt, zsh, and bash:

   ```bash
   pnpm acceptance:live-beta init --dir "artifacts/live-beta-acceptance"
   ```

6. Put all evidence files inside that directory. The gate rejects directories, empty files,
   symlinks, the manifest itself, files outside the session, and evidence reused for different
   scenarios. It records each file's size and SHA-256, so replacing a file after recording blocks
   the gate.
7. Populate every metadata field. Package and relay SHA-256 values must be the full 64 hexadecimal
   characters. The source commit must be the full 40-character SHA. Signing, Gatekeeper, and
   notarization statuses use the exact values below so an unknown or unverified result cannot pass.

   The following examples show shell-safe syntax. Run them on the coordinator machine, using the
   values observed on each package host. In PowerShell:

   ```powershell
   pnpm acceptance:live-beta metadata commit (git rev-parse HEAD) --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata version "1.4.1-beta.7" --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata productionDownloadUrl "https://social-harbor.com/download/..." --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata windowsVersion "Windows 11 24H2 build ..." --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata windowsArchitecture "x86_64" --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata windowsPackage "Harbor_1.4.1-beta.7_x64.msi" --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata windowsPackageSha256 "<64 hex characters>" --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata windowsSignatureStatus "valid" --dir "artifacts/live-beta-acceptance"
   ```

   In macOS zsh or bash:

   ```bash
   pnpm acceptance:live-beta metadata macosVersion "macOS ..." --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata macosArchitecture "arm64" --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata macosPackage "Harbor_1.4.1-beta.7_universal.dmg" --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata macosPackageSha256 "<64 hex characters>" --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata macosCodeSignStatus "valid" --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata macosGatekeeperStatus "accepted" --dir "artifacts/live-beta-acceptance"
   pnpm acceptance:live-beta metadata macosNotarizationStatus "accepted" --dir "artifacts/live-beta-acceptance"
   ```

   From either shell, also record `thirdProfilePlatform`, `thirdProfileArchitecture`,
   `relayArtifact`, `relayArtifactSha256`, `relayNamespace`, and `operator`. `sessionId` and
   `startedAtUtc` are generated by `init`; verify rather than replacing them. Record
   `evidenceRedactionAttestation` as `confirmed` only after inspecting the final evidence set. Every
   later `record` command clears that attestation and requires another final review.

## Run order

Use the detailed expected behavior in
[the reproduction matrix](live-beta-reproduction-matrix-2026-07-12.md). Run in this order so later
scenarios reuse only state established by earlier passing scenarios.

1. `P00`: record four distinct prerequisites: automated release gates, Windows package
   hash/signature, macOS package hash/code-sign/Gatekeeper/notarization, and deployed production
   download plus invite-handoff smoke. A source build is not packaged evidence. Capture the output
   of these repository gates as part of the automated prerequisite evidence:

   ```bash
   pnpm test:acceptance-gate
   pnpm test
   pnpm build
   cargo test --manifest-path src-tauri/Cargo.toml
   ```

2. `R01` and `R02`: create, lock, unlock, quit, relaunch, and recover both primary identities. Also
   exercise interrupted claim recovery with the relay available and unavailable, password mismatch
   and match, paste/password-manager input, keyboard/screen-reader status, and lock cancel/warning.
3. `R03`: use a clean browser with Harbor installed and absent. Test the deployed official HTTPS
   handoff with valid, malformed, and oversized payloads; require payload preservation, Open Harbor,
   install help, and no production 404.
4. `R04`: add both the official HTTPS and `harbor://` forms without editing. Reject malformed and
   oversized forms at the frontend and Rust boundary.
5. `R05`: request, review, accept, decline, retry, revoke, restart, and verify durable contact state
   and actionable notifications in both directions. Include duplicate/replay delivery.
6. `R06`: publish public and contacts-only content and prove authorized, unauthorized `charlie`,
   direct, relay/offline, and restart behavior. Revoke access and confirm stale cached authorization
   is rejected and prefetched private content is purged.
7. `R07`: exercise local and remote posts, edits, deletes, contacts, calls, and messages while the
   affected UI is open. Include duplicate events, reconnect, and profile switch; require bounded
   targeted refresh without manual reload or cross-profile state.
8. `R08`: transfer declared media with slow/chunked, offline/retry, unavailable, and hash-failure
   fixtures. Require queued/discovering/transferring/progress/ready/retrying/failed UI rather than an
   empty attachment.
9. `R09`: reconnect after offline authorized publishing. Verify cursors, jitter/backoff, bounded
   concurrency/storage, eviction, revocation purge, profile isolation, and no unauthorized fetch.
10. `R10`: receive messages and incoming/missed calls in foreground and background. Verify safe
    verified-name previews, navigation/actions, deduplication, read state, mute controls, and restart
    persistence without exposing private content.
11. `R11A`, `R11B`, and `R11C`: follow
    [the Windows/macOS call checklist](windows-macos-call-acceptance.md). For voice and video record
    ring/accept/reject, both directions, bidirectional media, controls, permission denial/recovery,
    hangup/relaunch, and direct plus TURN/NAT behavior. For the three-profile group record roster
    convergence, join/leave/rejoin, audio/video, one-participant failure isolation, capacity-limit
    rejection, and honest TURN diagnostics.
12. `R12`: verify general safe metadata cards plus consent-aware YouTube, SoundCloud, Spotify, and
    TikTok embeds with accessible fallback. Attach prerequisite SSRF/private-network, redirect,
    size, unsafe-scheme, tracking, provider, consent, and offline test evidence under `P00`.
13. `R13`: validate modal compose draft/attachments/visibility/failure/focus restoration; persistent
    All/Images/Video/Audio filters; one-time closable onboarding with Docs/Quick Start; and internal
    named bug-report navigation.
14. `R14`: traverse shared controls with pointer and keyboard on both platforms. Verify hover,
    pressed, focus, selected, disabled, loading, shortcuts, text-editing safety, assistive technology,
    reduced motion, and no layout shift.
15. `R15`: inspect contacts, calls, feeds, boards, errors, and notifications. Verified relay-qualified
    names or a safe unresolved state must replace peer IDs/public keys outside explicit diagnostics;
    include stale and revoked identity behavior.

For every scenario, save the required number of distinct sanitized screenshots, short recordings,
or log excerpts and record the result. Most scenarios require two evidence files, one for each
platform or direction. `P00` requires four prerequisite files and `R06` requires three for
authorized, unauthorized, and revoked access. Passing the substeps above requires a note that names
the observed variants; evidence count alone does not make an unperformed step pass. The CLI reports
the exact minimum if it is not met:

```bash
pnpm acceptance:live-beta record R01 pass \
  "Both packaged profiles resumed their verified names after relaunch" \
  "artifacts/live-beta-acceptance/r01-windows.png" \
  "artifacts/live-beta-acceptance/r01-macos.png" \
  --dir "artifacts/live-beta-acceptance"
```

PowerShell uses the same arguments; put the command on one line or use PowerShell's backtick line
continuation instead of the backslashes shown above.

Use `fail` for a reproducible product failure and `blocked` when the environment prevents the step.
Neither outcome permits publication.

## Evidence hygiene

Evidence may include qualified test names, timestamps, version metadata, sanitized transport class,
and UI screenshots made with test content. It must not include passwords, recovery material, private
keys, authorization tokens, TURN credentials, SDP, ICE candidate bodies or addresses, signatures,
raw private-message bodies, personal contact graphs, or private media. Crop unrelated desktop
content and inspect logs before attaching them. The CLI performs a conservative scan of bounded text
excerpts, but binary screenshots and recordings still require human inspection.

## Gate decision

Run:

```bash
pnpm acceptance:live-beta check --dir "artifacts/live-beta-acceptance"
```

The command exits nonzero until the manifest schema is exact, every required metadata field is valid,
every P0 scenario is recorded as `pass`, every meaningful note and timestamp is present, and every
required evidence file remains valid and uniquely assigned. A failed or blocked scenario returns to
its owning work item. `R16` is P2 product discovery and remains outside this P0 publication gate. Do
not publish the broad beta or mark `live-0730` done while this command is nonzero.
